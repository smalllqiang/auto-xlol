# Doctrine：默认战略与原则

AI-0 的交付物：把「大方向」从代码里抽出来，写成可读、可审的文本——目标是什么、
依据哪些机制、遇到情况怎么反应。**它是规则的来源，不是数字的来源**：所有数值仍由
页面和 planner 提供。AI 路径（ADR-031）只把本文件的原则转成提示词
（`autoplay/prompt.py` 的 `PRINCIPLES`），不会把本文件里的数字当常量。

分工：

- `docs/architecture.md`：代码怎么分层、数据从哪来、错误怎么处理。
- `docs/decisions.md`：为什么这样选（ADR，改架构前必读）。
- 本文件：玩这个号的目标、原则、假设；`docs/playbooks.md`：危机场景的确定性应对。

## 标注约定

| 标记 | 含义 |
| --- | --- |
| ✅ | 本实例页面验证过（注明日期或证据来源） |
| 📘 | 攻略先验（2023 纪元「猛犸」），机制可能变，只作假设（ADR-007） |
| ❓ | 待页面验证，**不要当常量用** |

数值一律从页面读，本文件不写死任何产量、成本、倍率。

## 一、机制事实（只列影响决策的）

### 资源与产能 ✅

- 三种基础资源 901 金属 / 902 水晶 / 903 重氢，分别由合金冶炼厂(1)、水晶催化厂(2)、
  重氢精炼厂(3) 产出。产量表（`page=resources`）给出基础产能、建筑贡献、加成、
  仓容、每小时/每天/每周产量。
- 每级增产量用页面观测值自校准：`observed × (1.1 × (L+1)/L − 1)`，不写死
  universe speed 或加成（ADR-004）。首次建造（等级 0）无法估算收益，只标「补齐产出」。

### 爆仓 ✅（2026-11-18 确认）

- 资源达到仓容后，对应生产建筑停止生产，资源不再增长；资源量本身可以远超仓容
  （当前账号被朋友赠送过大量资源），**不要**把「资源不涨」当成采集断档。
- 爆仓时产出建筑的回本估算失效：planner 把 `payback_hours` 置 `null`、候选排到末尾，
  并在 `notes` 汇总。仓容只来自产量表；概览量只用于判断占用率。

### 电力（幽能）✅（2026-11-18 核实）

- 幽能 911 是**速率资源**，不是库存：
  - 产量表的 911 `total` = **净产**（三厂消耗已经扣掉，负数表示缺电）；
  - 概览的 911 `capacity` = **毛产** = 净产 + 三厂消耗（页面显示成 `净产/毛产`
    的百分比条，实测 `392 K/600 K`、65%）；
  - 概览的 911 `amounts`（`data-real`）= 毛产 + 净产的**合成值**，不是库存，
    两天不变而净产 +392,000/h 已证明这一点。**不要**拿它和仓容比较，也不要拿它
    判断可负担性。
- 净产为负 → 三厂按比例减产（📘 攻略 1.4：电力不足有减产 debuff）。planner 在
  净产为负时给幽能发电站 `priority=1`、排到产能候选最前，并在 `notes` 提示。
- 幽能门槛：引力子技术这类需求的「资源」是电力，**只检查不消耗**（📘 攻略 2.1）。
  游戏检查的是毛产：实测需求 765,000、页面给出的可用值 600,017。所以缺口要靠
  提高毛产（发电站、📘 太阳能卫星），不是靠攒资源。
- 卫星补电、反幽能反应堆是攻略里的替代方案 📘，本实例尚未接入，不要假设可用。

### 依赖与队列 ✅

- 前置条件直接写在页面上（`"自律工厂 等级 5 (0/5)"`），planner 逐层展开成 blocker；
  解析失败只记 `notes`，不静默（ADR-003）。
- 建造 / 科研 / 船坞各自一条队列；研究进行中升级科研实验室会被游戏拒绝（实测），
  执行器已在 `research_queue` 非空时跳过该动作。
- 一次只推进一个动作；队列忙时跳过对应类型（ADR-005）。

### 可负担性 ✅

- 以研究/建筑页的 `costOverflow`（游戏自己算的净缺口）为准，页面没有时才退回
  本地资源量相减（ADR-012）。概览的幽能尤其不能当净可用，见上。
- 预检查被拒（`ActionRejected.before_post`）可以让本轮换下一条候选，其余拒绝
  不自动重试。

### 探险 ✅

- 航道数由探险技术（124）与加成决定；`stay_time=0` 会被游戏以「无效返回时间」
  拒绝，必须取第二步页面的 `staytime` 选项（1..探险技术等级）。
- 每轮重读探险报告再决定发送多少队，发送与召回都默认预览、需显式 allow-list
  （ADR-013–017）。探险积分目标是 50 万 fleetPoints（📘 攻略 1 阶段目标）。

### 签到 ✅

- `page=bonus` 的 GET **就是领取**，写入 24h 冷却；冷却期再访问只 302 回概览。
  所以只通过概览导航判断可用性（ADR-023），不要拿签到页抓样本。

## 二、阶段与默认 directive

当前默认策略就是 `autoplay/phases.py` 里的三段式：

| key | 名称 | 目标 | 目标形态 | 进入条件 | 完成条件 |
| --- | --- | --- | --- | --- | --- |
| `pre_gravity` | 种田初起 | 建成资源处理单元 | 建筑 81 ≥ 1 | 资源处理单元 < 1 | 81 建成 |
| `expedition_prep` | 探险准备 | 探险技术升到 9（解锁第 3 条航道） | 科研 124 ≥ 9 | 81 已建成 | 124 ≥ 9 |
| `expedition` | 探险纪元 | 攒够 50 万 fleetPoints 并维持探险 | milestone | 124 ≥ 9 | 📘 未定义（里程碑，暂只输出产能候选） |

阶段判定只看页面事实（等级），不看时间（ADR-003）。攻略把游戏分成五段
（种田初起 / 引力纷争 / 探险纪元 / 高级资源探索 / 飞升一瞥），本仓库目前只建模
前三段，且把「引力纷争」并入 `pre_gravity` 的依赖链（资源处理单元 → 引力子技术
→ 科研实验室）。

**默认 directive v1（AI-1 已落地：`autoplay/directive.py`，文件在
`state/directive.json`，校验失败自动回退）**：

```json
{
  "version": 1,
  "source": "default",
  "phases": [
    {"key": "pre_gravity", "name": "种田初起", "goal": "建成资源处理单元",
     "goal_kind": "building", "goal_element": 81, "goal_level": 1},
    {"key": "expedition_prep", "name": "探险准备",
     "goal": "把探险技术升到 9 级（解锁第 3 条探险航道）",
     "goal_kind": "research", "goal_element": 124, "goal_level": 9},
    {"key": "expedition", "name": "探险纪元",
     "goal": "攒够 50 万 fleetPoints 并维持探险",
     "goal_kind": "milestone", "goal_element": 0, "goal_level": 0}
  ],
  "constraints": {
    "one_action_per_round": true,
    "require_allow_list": true,
    "respect_queues": true,
    "skip_when_unaffordable": true
  },
  "risk_posture": "conservative",
  "expires_when": "阶段目标达成"
}
```

约束解释：directive 只说目标、约束、风险姿态和失效条件，**不说具体动作**；所有
数字由代码从页面注入。AI-0 不引入运行时 AI，仍符合 ADR-006。

**验收**：默认 directive 在 `tests/fixtures/` 上产出的计划与当前逐字段一致，已由
`tests/test_planner_golden.py` 冻结（阶段、目标、8 条候选的顺序/等级/回本有无/
优先级、notes）。

## 三、原则（代码已实现；改之前先读）

1. **回本优先**：产出建筑按「等价投入 ÷ 每小时增量」排序，追求最高回本率（📘 攻略
   1.3「追求资源的回本率是最高要求」）。唯一例外是幽能发电站——电力是速率，按
   净产报告，不按资源回本。
2. **爆仓不投产出**：产量不再累积时，回本数字是假的；置 `null` 并排到末尾。
3. **先解锁后生产**：当前阶段目标及其依赖链（blocker）永远排在产能候选前面。
4. **可负担性看页面缺口**：用 `costOverflow`，不用概览资源量。
5. **默认不动手**：`execute_plan` 默认 dry-run；真实执行要显式 `dry_run=False` +
   allow-list；一次一个动作；`state/STOP` 存在时拒绝运行（ADR-005）。
6. **被拒不重试**：预检查拒绝可换下一条候选，其余拒绝只记录（ADR-012）。
7. **事件只告警**：消息/战斗/能源/断档触发 alert 或 info，不改支出；需要停就
   `--pause-on-alert`（ADR-009）。
8. **改生产比例要过闸**：`prod[]` 只能整表提交（缺项当 0），写入要 `--execute` +
   allow-list 并按页面回读验证；缺电时默认只把消耗最大的厂降一档（ADR-028）。

## 四、假设与待验证

| 项 | 状态 | 影响 |
| --- | --- | --- |
| 攻略对应 2023 纪元，与本实例可能有差异 | 📘 ADR-007 | 只当先验；数值全部从页面读 |
| 幽能毛产模型（`capacity` = 净产 + 消耗） | ✅ 2026-11-18，样本有限 | 若换实例请用同样方法复核 |
| 卫星/反幽能反应堆补电 | 📘 未接入 | 不要假设代码会用 |
| 净产为负时的减产比例 | 📘 未量化 | planner 只按符号判断「缺电」 |
| 殖民、多星球调度 | ❓ `control` 面板未解析 | P2-3 的前置 |
| 探险纪元的完成条件 | 📘 「50 万 fleetPoints」 | 只作为里程碑文本，不参与判定 |
| 生产比例写入 | ✅ 2026-11-18 实机验证 | 刻度是百分数 0–100、步长 10；缺电只降一档 |
| 威胁阈值（60 分钟 danger / 24 小时 watch） | ✅ 2026-11-18 实现，经验值 | 太吵就调宽，改前看 ADR-026 |

## 五、维护方式

- 机制事实变了（页面改版、实例换服）：先改本文件，再改代码，最后补 golden 测试。
- 原则变了：先改 `docs/decisions.md`（新增 ADR 或标注取代），再改本文件、
  `autoplay/prompt.py` 的 `PRINCIPLES` 与代码，保证三处一致。
- 本文件不记录历史；历史看 `git log` 和 ADR。
